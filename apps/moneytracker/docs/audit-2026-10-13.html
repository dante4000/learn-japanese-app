Vault audit

13 October 2026 · Changes on main · Astra second review

Scope and outcome

All 31 component files received a source review. API routes, storage, sync, CSV parsing, and domain tests were also reviewed. This is a source audit with server checks. It is not a certification that all device, browser, or bank flows pass.

  • Fixed card credit projections and invisible bars.
  • Fixed chart filters, keyboard access, reduced motion, and narrow layouts.
  • Fixed form labels, file selection, save feedback, mobile navigation, sign-out feedback, and empty-state entry points.
  • Rejected invalid API input and CSV dates or amounts.
  • Preserved recurring streams after a failed provider refresh.
  • Storage failures now propagate instead of appearing as empty data. Added a dashboard retry screen.
  • Updated Next.js and dependencies. Added repeatable test and type-check commands.

Validation

  • 67 domain and storage tests passed.
  • Final lint, TypeScript, production build, and diff checks passed after edits.
  • Ten authenticated page routes returned 200 in local server smoke checks.
  • Five write routes returned 400 for null JSON and invalid fields. No valid financial write was performed.
  • Production dependency audit: zero reported advisories.
  • Chrome login screen inspected. Full authenticated browser and bank OAuth testing remain unverified.

Remaining limits

  • Distributed write races remain possible with the Blob read-modify-write backend. Sync now reloads edits after its network call, but this does not provide cross-instance transactions. A storage backend with atomic updates is needed to close this risk.
  • Five development-only dependency advisories remain in the ESLint glob chain. npm proposes a breaking downgrade. It was not applied.
  • Checks ran with Node.js 26.11.1. The project declares Node.js 22.
  • Real bank linking, live sync, and authenticated mobile browser interactions were not exercised.
  • Opus agents are unavailable in this session. Astra and the available review agent were used.

“Reviewed” means source inspected, including interaction and integration paths. It does not mean every component was tested in a live browser.
