Vault audit

13 October 2026 · Second audit · Main branch · Astra and Claude Opus reviews

Scope and outcome

Reviewed all 33 component files, app pages, API routes, storage, sync, CSV ingestion, and financial calculations. Fixed defects and checked the changes with tests, private transaction reconciliation, and authenticated browser checks. This report does not certify bank-feed completeness or every browser and provider flow.

  • Refunds reduce spending when posted. Card payments and transfer legs do not inflate income or spending.
  • Rent estimates follow dated revisions and inclusive end months. A real posted bill suppresses its estimate, including partial bills and bills followed by refunds. Hidden and pending rows do not suppress estimates.
  • Estimated bills have separate labels and totals. Housing filters preserve utilities. Bilt and card rewards remain explicitly identified as estimates.
  • Income can be split by exact normalized source. Employer-paid studio support is separate from bank deposits. Removed the old phantom-income implementation.
  • Possible duplicate charges have exact-row review, dismissal, and restore actions. Dismissal does not alter spending.
  • Storage uses conditional Blob writes and deletes, atomic local writes, and local process locks. Migration preserves existing metadata. Institution claims prevent concurrent duplicate bank connections.
  • Live verification found that compressed Blob responses supplied weak ETags and caused false write conflicts. Reads now request identity encoding. A Brotli regression fixture and a large disposable live probe verify the strong-ETag path.
  • CSV overlap checks prevent double imports. Pending-to-posted transaction updates retain user edits. A failed secondary refresh returns a visible warning after a successful save.
  • Shared owners now handle rent timelines, recurring monthly amounts, CSV overlap checks, API conflict responses, and Plaid Link loading.
  • Rent, studio-support, and transaction editors share saved feedback and bounded refreshes at 10, 30, and 65 seconds. Saves are never repeated by the refresh logic.
  • Phone layouts use larger targets and inputs, wrapping controls, scrollable tables, and safer chart dimensions. Accounts display exact cents.

Confirmed accounting settings

The user confirmed a home-rent end month, an ongoing employer-paid studio contribution, and two fee classifications. Keep actual garage charges separate. The studio start month is approximate. These values are saved as private production settings. Both rent revisions, employer support, and both fee categories and notes were verified in the live app.

Validation

  • 163 tests passed on Node.js 22.23.3. Regression cases cover rent, refund timing, income sources, rewards, duplicates, ingestion, storage conflicts, migration, and bank-link failure handling.
  • Lint, TypeScript, production build, and diff checks passed.
  • Thirteen authenticated local page routes returned HTTP 200.
  • Reviewed responsive layouts at phone widths of 320 and 390 pixels. Checked duplicate review/dismiss/restore, the rent editor, and income-source and employer-support controls. Checked tablet navigation at 768 pixels.
  • Reconciled 4,784 exported transactions across 8 transaction-bearing accounts and 29 months. Per-account, category, and monthly cash-flow totals matched the classified transactions. Production has 11 linked accounts; 3 have no exported transactions.
  • A fresh production export retained all 4,784 transaction IDs and amounts. The two confirmed fee categories and notes persisted. All effective categories matched the audited classification rules.
  • All 11 live account balances sum exactly, to the cent, to the displayed assets, liabilities, and net worth.
  • Verified conditional write, stale-write rejection, and conditional deletion against a disposable Blob probe. Removed the probe.
  • Astra reviewed rent rules again after the last refund fix. Three independent Claude Opus passes used model claude-opus-5-5. The final reported rent/refund defect was fixed and covered by tests.
  • Production dependency audit reported zero advisories.

Remaining limits

  • The export contains app records. It cannot prove that banks delivered every transaction or that balances match independent bank statements. User-confirmed studio support is not a bank deposit.
  • Reward projections depend on merchant coding, eligibility, and original transaction history. Confirm actual awards with the issuer.
  • Real bank linking, OAuth, and a new live provider sync were not exercised during this audit.
  • Conditional writes protect each document. Updates across separate documents are not one atomic transaction. Orphan institution claims fail closed and need verified operator cleanup.
  • Public Blob changes can take up to 60 seconds to appear after a successful save. A production edit showed this delay and appeared after a later refresh. Conditional writes still reject stale updates. Wait one minute, then refresh before submitting the same change again. See Vercel Blob caching.
  • Five development-only dependency advisories remain in the ESLint glob chain. No compatible fix was available during the audit. npm proposed a breaking downgrade, which was not applied.
  • Mobile source fixes cover all components. Browser checks covered key flows, not every state on every device.
